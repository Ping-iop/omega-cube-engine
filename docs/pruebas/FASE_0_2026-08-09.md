# PRUEBAS FASE 0 — Split-brain + corrupción
Fecha: 2026-08-09 22:28 UTC-5

## Hallazgo crítico previo (no estaba en el plan)
El store único `memory/omega_cube_memory.json` estaba **CORRUPTO a 926 MB**
(debía ser ~48KB/28 nodos). JSON truncado a EOF (char 889.517.264), con el array
`axiom_ids` repetido decenas de millones de veces (5 IDs en ciclo).

**Causa raíz:** `OmegaCubeEngine.load()` NO era idempotente. Append-eaba axiomas
e insertaba en el índice sin limpiar. Con doble `load()` (auto-load de `__init__`
+ `load()` explícito en indexer/MCP), los axiom_ids se duplicaban en cada ciclo
save/load → crecimiento exponencial 5→10→20→…→37M IDs → proceso muere mid-save.

**Fix aplicado (3 parches):**
1. `engine.py::load()` ahora hace reset de `self.nodes`, `self.index`, `self.axioms`
   antes de restaurar → idempotente.
2. `scripts/omega_auto_indexer.py`: eliminado el `engine.load()` redundante.
3. `omega_cube/omega_cube_mcp_server.py`: eliminado el `engine.load()` redundante.
4. Bonus: `telemetry.json` añadido a `STATE_FILES` (se auto-ingería como basura).

**Recuperación:** el dict `"nodes"` se escribe ANTES de `axiom_ids` → estaba intacto.
Se extrajo con `json.JSONDecoder.raw_decode()` y se reconstruyó un store limpio
(58 nodos recuperados, luego 49 tras limpiar basura de telemetry).
